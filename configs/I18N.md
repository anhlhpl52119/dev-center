## Overview

- Separate the build and runtime processes to generate physical files or maintain the most up-to-date multilingual
  information.

- The reason for performing the merge logic at both stages is as follows:

  - To avoid the issue of missing resources due to CDN problems during runtime.
  - Generate language resources during the build process for deployment purposes.
  - Enable updates to CDN-serviced resources without requiring redeployment.
  - Update the runtime to display the latest information to the user.

- The current mechanism for loading locale messages works as follows:

1. At runtime, the application loads locale messages from the i18n/default/{locale}.ts file.
2. If the loading process fails or the requested key does not exist in the default file, the application then tries to load locale messages from the i18n/fallback/{locale}.ts file as a backup (generated at build-time, merge from CDN, seed-data...).
3. If the key still cannot be found in the fallback file, the application loads the fallback locale, which is currently set to English.

## Features

**These are its features**:

1. Resources are created during the build process (when generating distribution files).

- Retrieve language-specific resources from the CDN.
- Merge the language resource file from the universal-seed with the one from the CDN.
- Transform the resource file into a flattened structure.
- Format the modified resource file according to the prettier rules.
- Create a formatted file.

2. Synchronize resources during runtime (when executing in the browser).

- Retrieve the corresponding language resource from the CDN.
- Merge the language resource file from the universal-seed with the one from the CDN.
- Transform the resource data structure into a flattened structure.
- Synchronize the updated data with the i18n instance(here is the version of nuxtjs/i18n: ^8.0.0-beta.12)

## gitignore

Please add `i18n` folder to the [.gitignore](../.gitignore) file.

- The i18n resources are generated both during server startup on the developer's PC and during the build process.
- Since the multilingual resource files are not intended to be tracked by git version control, they should be excluded.
- Only the latest data is necessary during the build, so the i18n folder should be excluded from git version management.

## Configuration

<details>
<summary>
1. Let's get started by adding the module to nuxt.config.ts

For example:

</summary>

```bash
export default defineNuxtConfig({
  modules: ['@nuxtjs/i18n'],
  hooks: getHooks({ useHttps, isProduction, RUN_TYPE }),
  i18n: getI18n(),
});
```

</details>

2. Then, create the configuration files to retrieve the config options.

You can use the following code bellow in files:

- [configs/hook.ts](hook.ts)

  - This file is used to create resources during the build process (when generating distribution files), using the `buildI18n()` function in the `build:before` lifecycle hook.

- [configs/locale/build.ts](locale/build.ts)
  - Get all multilingual resources from the CDN.
  - Merge the seed-universal locale file with the CDN locale file.
  - Convert the nested object to a flattened object.
  - Create the i18n floder.

The i18n structure consists of two folders: i18n/default and i18n/fallback.

- i18n/default contains locale files that fetch dynamic locale messages via CDN URLs.

- i18n/fallback contains locale files that are locale message objects, which are created by merging data from CDN, seed-data, and defaultLocaleMessage, and then flattened.

**Why are there two folders?**

- The reason is that at run-time, i18n will load files from the respective i18n/default/{locale}.ts directory.
- Each file in this folder contains a function that executes loading locale messages from the CDN (then merging seed-data and defaultLocaleMessage).
- In case there is an error during the fetch from CDN, the i18n will fallback to the corresponding local files in i18n/fallback.

- [configs/locale/runtime.ts](configs/locale/runtime.ts)
  It contains the function `getResourcesByLocale()`, which is used to fetch resource data from the CDN (and then merge locales, default, and flatten them) during runtime.

- [configs/i18nConfig.ts](i18nConfig.ts)
  - This contains the Nuxt/i18n options configuration. Example:

```shell
    strategy: '',
    detectBrowserLanguage: false,
    locales: locales: [
    {
    code: 'en',
    file: 'en-US.json'
    },
    ...
    ],
    lazy: true,
    langDir: '',
    defaultLocale: 'en,
    vueI18n: './i18n.config.ts', // contains fallback locales...
    precompile: {
    strictMessage: false, // The locale message can contain HTML tags
    escapeHtml: true // Determine whether to escape HTML tags if they are included in the locale message.
    // If strictMessage is disabled by setting it to false, we recommend enabling escapeHtml.
    },
     experimental: {
      jsTsFormatResource: true // Configure the flag for experimental features of the nuxt i18n module.
    },
```

- [plugins/i18n.ts](plugins/i18n.ts)
  Since I use lazy loading, The locale messages with @nuxtjs/i18n Lazy loading is cached. So if the same filename is specified in files or other locales entries, once loaded, it will be used from cache.. More details can be found at [lazy-load-translations](https://v8.i18n.nuxtjs.org/guide/lazy-load-translations).

To solve this issue, I have created 3 hooks in plugins/i18n.ts to monitor when the user performs actions to switch languages, and to always prioritize loading from the CDN first. You can view a detailed explanation of the code in the `plugins/i18n.ts` file.

## Usage

You can use the useI18n() composable to access it. Example:

```ts
const { locales, locale, setLocale } = useI18n();
```

Please refer to the code in the file [components/navbar/Navbar.vue](../components/navbar/Navbar.vue)
to test demo.
Because I am currently using the 'no_prefix' strategy for i18n, when we switch languages from the select form, we have to use the `setLocale(locale)` function to perform the language switch.

## Other

Some variables have runtime configurations based on the RUN_TYPE used in the source code(`runtime/runtype/dev.ts`...):

- TRANSLATION_BASE_URL: hostname of CDN link
- TRANSLATION_FOLDER_NAME: path to folder
- TRANSLATION_FILE_NAME: path to file name
- TIMEOUT_DELAY_LOCALE: Represents the maximum wait time, in milliseconds, for fetching resource data from the CDN for i18n. Currently, I have set it to 2000 milliseconds, which is approximately 2 seconds.
- I18N_SEED: An object where the keys represent locale codes, and the values represent CDN links to the locale's seed source

Refer [Nuxt I18n docs](https://v8.i18n.nuxtjs.org/).
